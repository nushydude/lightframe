## Goal

Give thumbnails, previews, and tiles generated by LightFrame one explicit pixel/profile/alpha contract so generated media is consistent across Rust, WIC, WebView, and cache paths.

## Current Code Context and source evidence

Astra found LightFrame WIC format conversion is not explicit CMS and Rust-generated images lack an explicit ICC contract. Existing thumbnail/cache code lives in `src-tauri/src/thumbnails.rs` and frontend image services.

Verify all paths against the fresh `origin/main` when the task is selected. Existing code is partial evidence and may have moved; do not treat a task plan or the Astra review as proof that implementation is complete.

## Scope and constraints

Separate profile preservation from pixel transformation. Do not assume monitor correction; task 92 investigates WebView2/Windows evidence. Define no-profile, wide-gamut, gray, CMYK/YCCK, invalid/oversized ICC, alpha, and tile seam behavior. Resource limits stay in 53.

## Implementation steps

- Inventory every generated thumbnail/preview/tile path and its current pixel format/profile metadata.
- Define a typed internal colour representation and policy for preserve/convert/strip at generated-media boundaries.
- Implement deterministic handling for sRGB/wide-gamut/gray/CMYK/YCCK/invalid profiles and alpha.
- Ensure tiled and full preview paths use identical transforms and cache identity includes the colour policy.
- Add profile/colour metadata to diagnostics without storing user paths.
- Coordinate export policy with task 72 without duplicating its UI or metadata contract.

## Acceptance Criteria

- All generated preview/thumbnail/tile paths declare the same documented pixel/profile/alpha contract.
- Equivalent full and tiled output stays within the documented pixel tolerance and has no seam/alpha regression.
- Invalid or oversized profiles are bounded and use the documented fallback.
- Cache identity prevents a stale colour variant from being reused.
- No native monitor transform is claimed without task 92 evidence.
