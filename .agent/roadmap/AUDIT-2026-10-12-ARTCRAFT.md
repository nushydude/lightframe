## Executive decision

The migration is a staged evidence program. Reuse the existing LightFrame safety and product owners, add one canonical task per actionable October recommendation, and make every implementation independently reviewable. Existing feature code is recorded as partial evidence rather than silently treated as complete. The program does not claim Artcraft parity, Windows colour behaviour, format completeness, performance improvement, or implementation approval until a selected task supplies evidence.

Reuse the implemented resource policy (53), corpus (84), executor/cache epochs (54), reduced JPEG path (67), and RAF path (68). Remaining platform work prioritizes path/capability authority (51/52), Windows benchmark harness (86), pixel/property infrastructure (85), runtime/E2E (55), typed domain boundaries (58), and the action model (59). User-grant prerequisites (51/52) precede filesystem mutation, automation, export, and authenticated control. Every remaining selected delivery below is a separate future task branch/PR; completed deliveries are not restarted.

## Research amendments and limits

1. Task 50 is implemented before this program: current `Cargo.lock` has `quick-xml 0.41.0`, `Cargo.toml` pins remediated `little_exif` revision `1ca486b`, and the named advisory ignores were removed before PR #212. Mark it “Implemented; reverify” with current-lock/PR evidence; retain its historical specification.
2. Historical research: LightCraft's `JobPool` bounds workers but pushes into an uncapped `Vec`; closures remain uncancelable and shutdown can leave workers alive. Task 54's merged implementation is the authority; new work must preserve physical queue/job bounds, review admitted-byte coverage and truthful cancellation.
3. PhotoCraft limits permit 8 GiB and `2^30` pixels and are not total RSS caps; LightCraft's `WorkGate` allows an oversized sole job and urgent bypass. These are patterns to test, not policies to copy. Task 53 remains the sole resource-policy owner.
4. Selective RAW preview range discovery is RAF-only in the reviewed path: `raw/preview.rs:219`; the related `files.rs:743` extent growth and `fs_preview_loader:695` whole-file fallback still require caps. Tasks 68, 69, and 70 are separate container families; no sensor decode or sweeping camera claim.
5. Task 62 owns Undo Last Decision and complete curation-snapshot restoration. Task 76 extends that foundation to bounded history/redo/bulk and persistence acknowledgement; no filesystem or external-editor undo promise.
6. Artcraft contact sheets are raster pages packaged as PDF. Task 81 is a new bounded PDF export contract, not inherited image export capability.
7. Assisted-cull mutations that automatically Pick/Reject are excluded. Tasks 77/78/79 are display/advisory-only and cannot delete, move, or decide for a user.
8. Task 54 already owns stale-generation rejection, cache epoch/root retirement, disk publication, memory tile-source invalidation, and barrier-controlled regression tests. It must not be split into a competing cache task.
9. Task 66 owns queued edit-job intent and recovery. Task 82 owns only unqueued crop/rotation draft recovery with source-fingerprint checks.

## Phased dependency-aware program

The arrows below are direct implementation prerequisites. “Useful support” in a task file is evidence or reuse, not an ordering edge. The graph is acyclic; no parser or corpus task depends on a feature that itself consumes that parser or corpus.

Start remaining 85 and 86 early from immutable synthetic/licensed fixtures and matched Windows measurements; their infrastructure must not depend on the feature tasks it measures.

The new decode tasks may depend directly on 53 and 54; 71 may use 92's investigation as supporting evidence but must not require a native monitor transform.

### Phase 2 — media and identity foundations

Use 85 for pixel/property assertions and 86 for benchmark evidence as available.

## Reuse, licence, and provenance limits

Reuse algorithms and small interfaces only after reviewing their source revision, edition/MSRV, error model, and resource bounds. Artcraft manifests reviewed here declare MIT OR Apache-2.0, but adapted code keeps notices and source revisions. Do not import branding, individual assets, corpora, fonts, profiles, or model weights without separate provenance. Do not reintroduce LightCraft's older `quick-xml` minor. HEIF dependencies and distribution licensing belong to task 89. Full Artcraft session/catalog/command/history/export/autosave/UI/memory systems are examples, not dependencies.
