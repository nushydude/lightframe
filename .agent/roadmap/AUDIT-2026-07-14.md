## Confirmed Bugs and Reliability Gaps

### P0 - Folder sorting can produce the wrong order

Evidence:

- `useImageNavigation.ts` returns early when `sortOrder === 'name'`. After sorting by size, date, or
  random, selecting Name therefore leaves the previous ordering in place.
- `imageSorting.ts` uses `sorted.sort(() => Math.random() - 0.5)`. A random comparator violates the
  comparator contract and does not produce an unbiased shuffle.
- Date and size sorts have no filename/path tie-breaker. Equal values therefore inherit whichever
  order happened to exist before the sort.

Action: implement task 42 before expanding sort functionality.

### P1 - Invalid persisted settings can enter typed application state

Evidence:

- `settingsFromRust` uses a generic `stringSetting` cast for `sortOrder`, `mouseWheelBehavior`, and
  `defaultFitMode`. Any non-empty string is accepted even when it is not a supported value.
- `settingsStore.updateSettings` logs write failures but leaves the optimistic value in the UI and
  exposes no save-error state or retry action.

Action: implement task 48.

### P1 - Image collections are not keyboard-accessible controls

Evidence:

- Thumbnail items and contact-sheet items are clickable `<div>` elements without button role,
  focusability, or an accessible image name.
- ContactSheet registers a window-level handler that treats every Enter press as “exit grid”, even
  when focus is on an interactive toolbar control.

Action: implement task 47.

## UI/UX and New Functionality Opportunities

### P1 - Put active-folder sorting where users work

Sorting is a navigation operation, but its only control is a global setting. Add an active-folder
sort menu to viewer and contact-sheet actions, add ascending/descending choice, and expose created
and modified dates separately. See task 43.

### P1 - Make slideshow configuration understandable in context

Shuffle itself is implemented. The improvement is to expose a labeled slideshow-options control and
show the effective mode while the slideshow runs. Do not build a second shuffle engine. See task 44.

### P1 - Complete endpoint navigation

Add Last next to First/Previous/Next, and rename the landing-page action so “Home” has only one
navigation meaning. See task 45.

### P2 - Add filename search to the contact sheet

Large folders are virtualized visually but cannot be narrowed by filename. Add a local,
non-destructive search that preserves source indexes, selection, sort order, and curation filters.
See task 46.

### P2 - Keep the display awake during presentations

A desktop slideshow may be interrupted by the Windows display timeout. Add a narrowly scoped native
display-sleep inhibitor that is acquired only while a slideshow is actively advancing and is always
released on pause, stop, window close, and error. See task 49.

## Performance and Maintainability Findings

These already have roadmap tasks. They were re-scoped in this audit where necessary so an
implementer does not have to choose between multiple architectures.

| Priority | Existing task | Finding |
| --- | --- | --- |
| P1 | [35 - Scalable folder catalog](tasks/35-scalable-folder-catalog.md) | The frontend keeps full arrays and repeatedly performs linear path lookup. Task 35 is now explicitly limited to revision-scoped path indexes; paging is a later task. |
| P1 | [36 - Slideshow large-folder reconciliation](tasks/36-slideshow-large-folder-reconciliation.md) | `useRef(images.map(...))` evaluates the O(n) map on every render, even though `useRef` ignores later initializer values. Shuffle reconciliation should key off an image-list revision. |
| P2 | [37 - Scalable curation persistence](tasks/37-scalable-curation-persistence.md) | Curation commands hold a process mutex and perform full JSON filesystem work directly in async command bodies. Task 37 is now limited to `spawn_blocking` plus atomic JSON replacement; no database migration. |
| P2 | [41 - Edit queue immutable updates](tasks/41-edit-queue-immutable-state-updates.md) | The queue mutates job objects in place and uses `jobsVersion` as a manual invalidation signal. |

Fallow also identifies `ViewerChrome.tsx` (2,788 lines) and the global key handler in
`useKeyboardShortcuts.ts` as high-complexity hotspots. Do not start a broad refactor in the same pull
request as tasks 42-49. Extract only the helpers/components required by each task; schedule a
behavior-preserving decomposition audit after the user-facing P0/P1 work is complete.

## Global Definition of Done for Every Task

An implementation is not complete unless all of the following are true:

- The task's acceptance criteria and named regression tests pass.
- The current image remains selected by path whenever ordering or filtering changes and that path
  still exists.
- Folder refresh, folder watcher updates, curation filters, contact sheet, compare view, projector
  synchronization, and slideshow behavior are checked when the task changes image ordering.
- Settings changes remain backward-compatible with an existing `settings.json` unless the task
  explicitly defines a migration.
- No new dependency is added unless the task explicitly permits it.
- `pnpm run test:run`, `pnpm run build`, and the task-specific checks pass.
- If Rust changes, also run `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`,
  `cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings`, and
  `cargo test --manifest-path src-tauri/Cargo.toml`.
